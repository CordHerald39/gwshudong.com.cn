## 把故障分成三类

“找不到打印机”可能是设备发现失败，“NAS 域名打不开”可能是名称解析失败，“内网 IP 也连不上”才需要重点看路由。先记录设备地址和使用方式，避免三类问题都用一条 DNS 修改处理。

## 保留基础对照

在自有终端上暂停 TUN，验证同一内网资源是否恢复。若暂停后也失败，先检查设备本身、网线、无线隔离或访客网络。访客 Wi-Fi 常与家庭设备隔离，不能假设它与主网络互通。

## 先看普通 IP，再看名称

用你已知的内网 IP 访问资源作为辅助测试。HTTPS 名称不匹配时不要继续登录；只记录是否建立连接。IP 可达但名称失败，再核对系统 DNS、客户端 DNS 与 hosts；自动发现失败则查看应用所需的多播或发现机制，不把它当普通域名。

## 核对 TUN 路由范围

mihomo TUN 的自动路由和路由排除设置需要按操作系统及内核版本核对。只对确认需要的内网地址范围作例外，并确认 DNS 与流量路线配合。不要复制一个覆盖所有私网与公网的“万能配置”，也不要在公共网络开放发现服务。

| 对照 | 更可能的调查方向 |
| --- | --- |
| TUN 开关都失败 | 设备与基础局域网 |
| IP 可达、名称失败 | DNS 或名称发现 |
| 只有 TUN 开启失败 | 路由范围与接管设置 |
| 只有访客网络失败 | 无线隔离与网络拓扑 |

修改后重建应用连接，同时复核公网访问；无改善便恢复旧配置。基础操作见[连接排查](/tutorials/connection-check/)。
